# Threat model

PR source, comments, configuration guidance and model responses are untrusted. Raw webhook signatures are checked before intake; command authors require write/maintain/admin repository permission checked with the installation token. Bot events are ignored. The worker uses a repository-scoped token; Git passes it through environment configuration, not URL or command arguments. Git fetch disables hooks, filters and submodules. No checkout, dependency install, build script or test runs from a PR.

File paths are checked for traversal and only Git blob contents are read. The code graph parses blobs with tree-sitter grammars compiled to WebAssembly; parsing never executes repository code, and the parse cache stores only symbol names, line ranges and import specifiers (no source text). Review guidance comes from the trusted base and cannot authorize operations. The model receives bounded source snippets and may still be fooled by prompt injection; the verification pass checks an exact excerpt but is not a proof of correctness. Human review remains necessary.

The dashboard's OAuth token stays in an encrypted, server-side session cookie; server routes check GitHub repository visibility. Worker API calls require a shared secret. Keep `WORKER_SECRET`, App key, webhook secret and model key out of browser bundles, logs and source. Rotate secrets after exposure. Self-hosted Convex has its own license and admin key; the latter must never go to the worker or browser.

Remaining risks: an expired worker may race a GitHub publication despite preflight checks; webhook event payload shape and App permissions still need live verification; fixture tests are not a security audit. Provider bills can exceed configured estimates if prices are wrong or the provider bills failed attempts. Use network egress restrictions and isolate the worker from unrelated secrets in sensitive deployments.
