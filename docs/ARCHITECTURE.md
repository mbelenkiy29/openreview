# Architecture

GitHub signs a webhook over the raw body. A Convex HTTP action verifies it and atomically deduplicates the delivery and writes a job. A Docker worker claims a lease with a fence, fetches exact base and PR head objects with a repository-scoped installation token, reads rules from the base revision, prepares local diffs, retrieves TS/JS symbol references, and calls an interchangeable model adapter. The independent engine validates candidate schemas, changed lines, severity, and a second model challenge with a source excerpt. It records rejected candidates. The worker rechecks the head and lease, reconciles existing summary and inline markers, publishes advisory comments, then marks the job complete.

Automatic runs are keyed by installation, repository, PR, head and configuration version. New arrivals supersede queued automatic jobs. A prior successful head is used as an incremental comparison only if it is an ancestor of the new head; force pushes fall back to the base. Convex serializes claims and budget reservations. Each bounded model call reserves its maximum estimated input/output cost across per-review and monthly ledgers and settles once. Unknown provider prices are not silently treated as zero.

The worker's checkout is temporary and removed in `finally`. Convex stores compact findings and usage, not repository snapshots. The CLI invokes the same engine without Convex. The dashboard uses Auth.js GitHub OAuth and checks repository visibility on its server route before disclosing review history; it never sees the Convex admin key.

The GitHub API and Convex cannot share a transaction. Final SHA and fence checks narrow publication races but cannot eliminate a force push during the API request. Retried publication searches existing markers across pages before posting. The worker does not currently maintain a persistent source index or a durable external publication outbox.
